# R87 Winchester M1897 (development, not released)

Base commit: fdf3d50cba5688e7e5e5e25532df18c7b4635776 (R86, live).

The licensed Jaymod 2.0.0 M97 models, textures, sounds and parser-adapted weapon config are tracked in the enclosing Bombas project at `source/bombas-medic/r87-winchester/`, complete with an SHA-256 manifest. Packaged with `scripts/package_r87_winchester_assets.py`. Original Jaymod revision bbe44e0cca806d6b51260d48d4c11eab2b85bfe9, Apache-2.0 plus original id Software license. Do not use unlicensed replacement assets.

Do not release any M1897 server/client until all of the following are implemented and demonstrated together:

- Preserve all existing weapon values 0-55 and events. Add new IDs only at the end of shared weapon/MOD/item/stats tables and all dependent arrays in `src/game/bg_public.h`, `bg_misc.c`, `bg_classes.c`, `g_weapon.c`, `g_client.c`, `etbot/g_etbot_interface.cpp`, the relevant UI/cgame files and Lua interfaces. Maximum weapon bitset supports 64; do not exhaust these slots (StG44, BAR and PPSh are still planned).
- Server-authoritative close-range pellets with efficient network event aggregation, anti-lag, damage falloff, headshots/team damage, wall/world impact and honest kill credit. Do not spam one multicast event per pellet unnecessarily.
- Native engine `bg_pmove.c` must predict pump and interruptible individual-shell reload deterministically on client and server. Jaymod's `holdable[]`/`pmext` implementation cannot be copied verbatim, since ET: Legacy uses a different shared state. No new client executable or incompatible network fields.
- Render all MD3 model parts/skins and show firing, reload, pump, shell ejection, icons, first/third person and sounds with the existing client weapon parser. M97 `scaleFirstPerson` was unsupported and removed from the adapted `.weap` file.
- Correct soldier/class selection, ammunition, skill unlock, ammo packs, loadouts, pickups, dropped guns, special maps, team balance, bot ranges and cooldowns; no accidental changes to Nitro dual grenades or previous Class Stealing.
- Build five existing native client distributions and the Linux64 dedicated game module, exercise real ET:Legacy 2.86.2 human clients and mixed Omni-Bot 0.93 on stock/special maps, verify pure PK3 auto download with old cache, exact SHA, cgame compatibility, frame times, gameplay, and server rollback.

The R87 asset PK3 currently on VPS `/opt/bombas/releases/m1897_assets_r87_STAGED_20e1260d7e3f.pk3` is intentionally not in the active `/opt/bombas/legacy/`. Do NOT activate it until corresponding game and cgame release gates are met. Existing live R86 is untouched.

## 2026-10-30 intermediate implementation and native Linux QA

- Shared weapon ID `WP_BOMBAS_M1897=56`, appended after stock `WP_AIRSTRIKE=55`; append-only obituary MOD, weapon statistics, and item ID. Weapon bitset still below 64. Class primary slot offered to Allied and Axis Soldiers, with 8-shell tube and 16 reserve at spawn. New explicit `WEAPON_TYPE_SHOTGUN` avoids accidental rifle mechanics. Bank 3 supports 19 slots.
- Server-only eight authoritative pellet traces per shot, one anti-lag rewind around the whole blast, one body-ignore setup, uses built-in hit/damage/obituary and distance falloff. Maximum nominal close-up base damage is eight times nine; **damage/falloff fairness and multi-hit event bandwidth are not approved yet**.
- Client/server shared per-shell reloading uses preexisting predicted weapon state, weapon animation and weaponTime, **no new playerState network fields**. Begin/loop/finish animations 400/900/550 ms, empty begin 2000 ms, fast reload 600 ms per shell with skill. Uses one `EV_FILL_CLIP` per actual shell; waits for each stage and avoids firing while still loading. Mid-reload interruption by attack awaits native test.
- Local cgame supports eight M97 MD3 parts by extending render arrays, while retaining the historical original animated-weapon bit at 1<<7; the eighth M97 hand part is treated as static and follows its model tag. This deliberately does not reassign old animation bits or alter packet layout.
- Built on Linux x86_64 `qagame` and `cgame` with no compilation errors. Native official ET: Legacy 2.86.2 Linux64 two-client smoke on Oasis with real binds: `/team b 0 56 0` sets weapon 56; new 8-part model renders, official client registers m97.weap without warning after fixing the eight-part overflow. Xvfb screenshot shows HUD 8/16, one real `MOUSE1` shot reduces to 7/16, real R reload returns 8/15. Three more real shots produce 5/15, during reload 6/14, after reload 8/12, so per-shell reload (not instant full-clip refill) confirmed. Evidence `reports/r87_client_gate/{a.log,b.log,server.log,a_three_shots.jpg,a_multi_reload_mid.jpg,a_multi_reload_after.jpg}`. Embedded test server with two Omni-Bot 0.93 slots loaded 147 Oasis goals. Test server ran `sv_pure 0` for local QA; not a release quality FastDL test.
- Existing R86 server remains in production. R87 source and assets are development-only. Missing positive M1897 enemy damage/kill, live reload interruption and pump audio, accuracy/balance, shotgun shell casing visuals, bot use with fair range and reload AI, physical Windows/macOS runtimes and five client binaries, real FastDL/sv_pure, historical cache and all-map/performance regression.
