# R89 exact user-defined class matrix, M1897 HUD and friendly hazards

This commit is **not** a PPSh, StG44 or BAR implementation. Those planned weapons are pinned in `/home/debian/serwer-et/docs/BOMBAS_R89_USER_WEAPON_FF_SPEC_20261030.md` (and in the structured 9+5 backlog) and must use the exact class matrix when implemented. This change fixes the already-LIVE R88/R87 Winchester and teammate FF hazards.

M1897 axis+allies class primaries: Medic, Engineer, Field Ops, primary lobby selection. Soldier: M1897 NOT in `classPrimaryWeapons` or Soldier lobby; instead `SetWolfSpawnWeapons` always adds 16 shells reserve and 8 clip on top of selected primary. The native weaponbank-3 command (key `3`) explicitly alternates between Soldier's actual chosen primary `cgs.clientinfo[].weapon` and bonus M1897, using the same event/animation safety as native grenade switching. Engineer's rifle grenade and all other equipped weapons preserved. All alternate Soldier primary choices (MP40/Thompson, Panzerfaust, mortar, MG, flamethrower) eligible. The stale Soldier `sess.playerWeapon==WP_BOMBAS_M1897` from a previous release is normalized. Native client and dedicated server share the same class table. `SetWolfSpawnWeapons` is invoked by corpse class stealing also, which automatically picks up this behavior.

Icon root cause: `weapons/m97.weap` had two valid `weaponIcon` paths but no `weaponIconScale`. In `cg_newDraw.c`, width=MIN(size*weaponIconScale,rect->w), and cg weapon info is zeroed by `Com_Memset`, resulting in a zero-width icon. R89 companion M97 asset includes `weaponIconScale 1`, without changing other assets or R77 flames, no extra layers/draw calls. Screenshot official client on isolated Oasis `reports/r89_qa/weapon_126.jpg` displays M1897 silhouette at bottom right with 8/16 ammo; from the same game Soldier press3 screenshot series `soldier_3_press_{1,2,3}.jpg` alternates 8/16,30/60,8/16 with the icons present.

When `g_friendlyFire=0`, `G_LandmineThink` ignores teammates before checking collision (previous protection was commented out); `LandminePostThink` also excludes teammates during the post-trigger entity scan, preventing a friendly lingering over a triggered mine. FF enabled uses previous trigger rules. Opposing team always triggers. Molotov bot native steering `BombasRefreshFireThreats` records ownership and original connect-time; each bot filters teammate-owned flames with FF0 and no self exception if the bot owns the flame (self-burning possible per game design). Enemy flames and friendly flames with FF1 retain hazard avoidance. Filter also applies to alternate path clearance scoring to prevent sneaky avoidance. `G_BurnTarget` already prevented allied flame damage when FF0. No changes to R77 visual effect, particle, shader, geometry, or FPS timings.

Bot choice patch `tools/bombas/omni-bot/stage_r89_weapon_table.py` injects class-primary ID77 only for legacy classes Medic/Engineer/Field Ops, removes old R87 Soldier class PRIMARY. Soldier gets shotgun regardless in native `SetWolfSpawnWeapons` and `Bot_Event_AddWeapon` reports it to bot. Source original OmniBot 0.93 never overwritten.

Linux64 `qagame` and `cgame` compiler passed. Native isolated two official ET:Legacy clients on `:125/:126` and UDP28231 Oasis, real command `/team b 0 5 0` kept Soldier with chosen main, key3 switched new bonus M1897 and primary, `/team r 1 56 0` set Medic M1897 active; subsequent `/team r 2 56 0` / `/team r 3 56 0` accepted `lc=2/3` and `lw=56` for Engineer/FieldOps. Full screenshots/logs `reports/r89_qa/`. Native FF0 landmine trigger/movement and bot movement still need dedicated QA, and five-platform CI+pure FastDL+VPS guard before deployment.
